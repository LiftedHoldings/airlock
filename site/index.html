01The gap

A keypad that types into the model

In late August 2026, ElevenLabs Agents added caller keypad input. A caller can now press digits during a phone call, which is exactly what a payment needs. The catch is where those digits go: keypad digits are delivered to the agent's language model as an ordinary user message. A card number typed on the keypad becomes text in the model's context window.

ElevenLabs offers a setting for this, redact_input. Its documentation is precise about what it covers: it replaces keypad entries in stored transcripts, logs and analysis, and it says plainly that it

“does not hide digits from the agent during the live call.”

ElevenLabs documentation, redact_input

The obvious workaround is to isolate payment in a dedicated sub-agent and hand the call to it. We tested that against real agents.

Live finding · 2026-10-06

ElevenLabs re-sends the entire conversation, including typed digits, to the Custom LLM on every later turn — even after transfer_to_agent hands the call to another agent. Isolating payment in a sub-agent protects nothing.

Digits typed into the web widget's text box are also stored in the ElevenLabs transcript in plain text; redact_input covers keypad entries only.

There is no native secure-capture feature in the ElevenLabs changelog through 2026-09-28. The Stripe integration sends the caller a payment link, which means leaving the conversation to pay. If you want a caller to pay inside the call, the card has to pass through something — and today that something is the model.

Airlock changes what the model receives. Every model request from ElevenLabs goes first to a certified vault, which swaps keypad entries for short-lived tokens before anything else sees them. Below is the whole system, running live.

    03How it works

    Two proxies, one script, no card in the middle

    An ElevenLabs agent has a language model as its brain. With Custom LLM, ElevenAgents hands that thinking to an endpoint you choose, while voice, turn-taking and keypad input stay in ElevenAgents. The model behind it is the merchant's own — any OpenAI-compatible model — not an extra AI added by Airlock. Airlock sets the Custom LLM URL to a vault's inbound proxy. The vault inspects the request before it is forwarded, turns keypad entries into tokens, and passes the rest to Airlock, an open-source service that holds only tokens. Airlock either passes the turn to the agent's model — never with card data — or, during a payment, runs a deterministic capture script itself. To charge, Airlock calls the vault's outbound proxy with token references; the vault fills in the real values and posts to the gateway.

    Here is one card payment, step by step.

    1. The caller asks to pay. ElevenLabs posts the conversation to the Custom LLM URL — the vault inbound proxy — with the proxy key in a request header.
    2. Speech passes through. Nothing card-like is in it, so the vault forwards it to Airlock, which passes it to the agent's model (the merchant's own). When the caller wants to pay, Airlock opens a capture.
    3. The caller keys the card number and presses #. ElevenLabs delivers the digits as a user message. At the vault, the inbound transform replaces them with a token and a marker such as [[airlock:kp len=16 last4=1111 brand=visa]]. That marker is all Airlock ever receives.
    4. Airlock runs the script, not the model. While a capture is open, Airlock speaks fixed prompts — expiry, security code, ZIP, save the card?, confirm — and collects one token per field.
    5. The caller confirms. Airlock sends the outbound proxy a charge whose card fields are token expressions like {{ token }}. Airlock's own key cannot resolve them: detokenization lives on a separate vault application attached only to the fixed-destination outbound proxies. The proxy builds the gateway body itself and posts to NMI or Authorize.net.
    6. A reduced reply comes back. Status, response code, auth code, AVS and CVV results — no card data. Airlock deletes the tokens; they would expire after 10 minutes anyway.
    7. The agent tells the caller. The model sees only the outcome, the brand and the last four digits.

    Two ways to deploy it

    Payment desk (recommended). The main agent, Scarlett, runs on ElevenLabs' own hosted language model — no Custom LLM, no merchant model. When the caller is ready to pay, she uses ElevenLabs' native transfer_to_agent to hand the call to a payment-desk agent. The desk agent's Custom LLM goes through the vault to Airlock with the header X-Airlock-Mode: desk. On the desk no language model is called at all: Airlock scripts every word — “You're on the secure payment line. Say ready when you have your card or bank details.”, then the total and the keypad prompts (for an eCheck, the name on the account first) — charges through the vault, says “Thanks for calling. Goodbye.” and ends the call with the end_call system tool.

    Why the desk ends the call. ElevenLabs re-sends the entire conversation, typed digits included, to whichever agent speaks next; we proved this live for transfers between Custom-LLM agents. The main agent's hosted model is not behind the vault, so the desk must never hand back to it. It ends the call, or could transfer to a person. transfer_to_agent has no option to drop history today.

    Full conversation (Custom LLM). Every turn goes through the vault to Airlock, the merchant's own model handles the conversation, and the conversation continues after the payment. That is the design the step-by-step above walks through.

    04Why a middleware at all?

    What a vault transform can't — or shouldn't — do

    A vault transform can rewrite a request. It can't run a payment. Airlock exists for five jobs:

    1. State across turns. Which step the caller is on, the token ids, attempt counts and settled orders — the double-charge guard. Vault transforms are stateless.
    2. The amount comes from the merchant. Never from the model, never from the caller.
    3. Model routing. Ordinary turns stream through to the model; Airlock intercepts start_payment and runs the capture itself.
    4. A small card environment. About 200 lines run inside the vault. All business logic lives outside it, on tokens only.
    5. Observability without card data. The event stream that drives the live diagram above carries step names, brands, last fours and timings — never a card number.

    Option B: vault-only

    The alternative is to point the inbound proxy straight at the model and run the whole capture inside the transform. We didn't choose it. All business logic would become card-environment code; state would have to be rebuilt from the re-sent history on every turn; transforms have a 10–30 second limit; and every conversational turn would be buffered.

    When ElevenLabs ships native secure capture, jobs 1–4 move into the platform and Airlock disappears.

    Built-in protections

    • Airlock's key can only delete tokens. Detokenization lives on a separate vault application attached only to the fixed-destination outbound proxies, so even a key leaked from the Airlock host cannot send card data to another URL (tested: HTTP 403).
    • Card numbers are detected however they are written — separated by spaces, dashes, commas or slashes, typed in other digit scripts, or spoken as words.
    • A charge always settles. If the call drops mid-charge, the outcome is still recorded.
    • One order cannot be charged twice in a call.
    • Unclear gateway outcomes are never reported as “no charge”.
    • Confirming a payment requires keypad 1 or a clear yes.

    The 648 ms median is the full round trip from our test driver through Basis Theory to Airlock on DigitalOcean and back. Almost all of it is the vault hop.

    The vault proxy buffers streamed replies. Time-to-first-byte equalled total time in every sample, so a “one moment” sentence streamed by the model cannot be heard early — the caller would hear it together with the result.

    So the agent uses ElevenLabs' native soft-timeout fillers instead: “One moment.” at 2.0 seconds, then “Still working on that, thanks for waiting.”, then “Almost there.” They are static text on purpose. The alternative, model-generated fillers, would hand recent conversation context — which may contain keypad turns — to another model.

    Cold starts are real. A cold vault runtime added about 10.8 seconds to the first request. Airlock keeps the vault runtimes warm with a ping answered inside the vault, and pre-warms the outbound proxy as soon as the caller reaches the confirm step.

    Timeouts need room. ElevenLabs' default cascade_timeout_seconds is 4 seconds (range 2–15). A charge can take longer than that, so the demo agent is set to 15 seconds, and Airlock's capture guard prevents a double charge if ElevenLabs retries the turn.

    07What the tests changed

    Seven things we only learned by running it

    1. Sub-agent isolation doesn't work. The whole history, typed digits included, is re-sent to the Custom LLM on every turn, even after a transfer to another agent.
    2. NMI's duplicate check ignores the order id. The same card and amount are blocked for about 20 minutes regardless of order. Airlock now tells the caller “that payment already went through” instead of a generic failure.
    3. Authorize.net replies start with a UTF-8 byte-order mark. The reply has to be read with that in mind before it can be parsed.
    4. Authorize.net's sandbox rejects eCheck SEC code TEL (error 246; it must be enabled per merchant). The sandbox uses PPD as a stand-in.
    5. Both gateways require the account-holder name for eChecks. The agent asks for it in conversation before the keypad steps.
    6. Spoken card numbers are cut at the vault. When a caller reads a card out loud, the number is removed from the sentence and the rest of what they said survives.
    7. Timestamps looked like cards. Values such as 1791292673.7754595 tripped an early detector. Dots are no longer treated as separators.

    PCI scope

    SAQ A (r1, January 2025) can cover mail- and telephone-order merchants whose account-data handling is fully outsourced to PCI DSS compliant providers. In Airlock's design, card data exists only at ElevenLabs, the vault and the gateway. But Airlock directs the payment flow, so an assessor will likely treat it as security-impacting: expect a reduced set of controls, not zero.

    Software isn't PCI compliant; deployments are assessed. This is engineering guidance, not legal advice.

    10A recommendation for the ElevenLabs product team

    Two changes that would retire the workaround

    Everything above exists to stop one thing: keypad digits becoming a model turn. The platform could do that directly.

    1. Secure keypad capture

    • A payment tool arms secure capture.
    • While armed, keypad entries are held as secret values and never become a model turn. The platform speaks the configured prompts.
    • When the fields are complete, it calls the tool's webhook with the secret values substituted server-side — as secret__ dynamic variables already are in tool headers.
    • The model receives only approved or declined, the brand and the last four.
    • The values are dropped when the webhook returns, and never reach transcripts, logs or analysis.

    The webhook can post straight to NMI or Authorize.net, so the gateway's own vault becomes the only token store. No proxy, no $995 a month, no middleware.

    Native secure capture also lets the agent keep ElevenLabs' hosted model: no Custom LLM, no vault, no extra model box.
